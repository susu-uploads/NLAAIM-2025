## Архитектура

### 7.1. Парсинг корпуса

```text
+------------------+
| CLI / argparse   |
| --resume         |
| --output         |
| --manifest       |
+--------+---------+
         |
         v
+------------------+
| ParserConfig     |
| лимиты, домены,  |
| пути, User-Agent |
+--------+---------+
         |
         v
+------------------+      +----------------+
| ParserApplication| ---> | PageDiscoverer |
+--------+---------+      | поиск URL      |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | PageLoader     |
         |                | WebBaseLoader  |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | TextCleaner    |
         |                | очистка текста |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | CorpusStore    |
                          | JSONL + JSON   |
                          +----------------+
```

Скрипт сначала собирает внутренние ссылки сайта, затем загружает найденные HTML-страницы через `WebBaseLoader`, очищает текст и сохраняет результат в JSONL. Для устойчивости используется инкрементальная запись: если отдельная страница не загрузилась, остальные результаты не теряются.

### 7.2. Индексация

```text
+------------------+
| CLI / argparse   |
| пути, --rebuild, |
| --test-query     |
+--------+---------+
         |
         v
+------------------+
| IndexConfig      |
| параметры чанков |
| и embeddings     |
+--------+---------+
         |
         v
+------------------+      +----------------+
| IndexApplication | ---> | CorpusReader   |
+--------+---------+      | чтение JSONL   |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | DocumentPreparer|
         |                | Document + split|
         |                +----------------+
         |
         |                +----------------+
         +--------------> | ModelRuntime   |
         |                | embeddings     |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | ChromaIndex    |
         |                | batch insert   |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | RetrievalProbe |
                          | test query     |
                          +----------------+
```

Индексация отделена от парсинга, чтобы корпус можно было собрать один раз и затем пересоздавать индекс без повторной загрузки сайта. Добавление документов в `Chroma` выполняется пакетами, так как у Chroma есть ограничение на максимальный размер batch.

### 7.3. Консольная RAG-система

```text
+------------------+
| CLI / argparse   |
| --question       |
| --rerank         |
| --no-sources     |
+--------+---------+
         |
         v
+------------------+
| ChatConfig       |
| модели, retrieval|
| и генерация      |
+--------+---------+
         |
         v
+------------------+      +----------------+
| ChatApplication  | ---> | ModelRuntime   |
+--------+---------+      | LLM + embedder |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | VectorStore    |
         |                | Chroma load    |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | Retriever      |
         |                | MMR / rerank   |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | PromptBuilder  |
         |                | context prompt |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | QuestionAnswerer|
         |                | ответ по RAG   |
         |                +----------------+
         |
         |                +----------------+
         +--------------> | ConsolePrinter |
                          | ответ + ссылки |
                          +----------------+
```

При вопросе пользователя система извлекает релевантные чанки из `Chroma`, при необходимости применяет reranker, собирает контекст и передает prompt в локальную LLM. Ответ печатается вместе со списком источников, если не указан параметр `--no-sources`.

## Теория

1. **Что такое RAG?** RAG - это подход, при котором LLM отвечает не только на основе внутренних параметров, но и на основе внешнего контекста, найденного в базе документов. Сначала выполняется поиск релевантных фрагментов, затем они передаются модели в prompt.
2. **Зачем RAG нужен, если уже есть LLM?** LLM может не знать локальные или свежие данные, а также может ошибаться при ответах по фактам. RAG добавляет к вопросу конкретные документы и снижает зависимость ответа от памяти модели.
3. **Почему парсинг вынесен в отдельный скрипт?** Загрузка сайта медленная и зависит от сети. Если хранить корпус отдельно, индексацию и эксперименты с retrieval можно повторять без повторного парсинга.
4. **Почему индексация вынесена отдельно от чата?** Построение embeddings и запись в Chroma занимают время. Чат должен только загрузить готовый индекс и отвечать на вопросы.
5. **Что хранится в JSONL-корпусе?** Каждая строка содержит одну страницу: URL, заголовок, очищенный текст, время загрузки, название loader и длину текста. Такой формат удобно дописывать построчно и читать потоково.
6. **Зачем нужны чанки?** Веб-страницы часто слишком длинные для prompt и поиска целиком. Разбиение на чанки позволяет искать конкретные фрагменты, а не всю страницу сразу.
7. **Что дает перекрытие чанков?** Если важная фраза попала на границу двух фрагментов, overlap сохраняет часть соседнего контекста. Это уменьшает риск потерять смысл при разбиении.
8. **Что такое embedding?** Embedding - это числовой вектор текста. Близкие по смыслу фрагменты должны иметь близкие векторы, поэтому по ним можно выполнять семантический поиск.
9. **Почему используется multilingual embedding-модель?** На сайте ЮУрГУ есть русские и английские страницы. Мультиязычная модель позволяет искать по обоим типам текстов в одном индексе.
10. **Что делает Chroma?** Chroma хранит тексты, метаданные и их векторы, а затем быстро возвращает ближайшие документы по embedding пользовательского вопроса.
11. **Чем MMR отличается от обычного поиска ближайших соседей?** Обычный поиск выбирает самые близкие фрагменты, которые могут быть почти одинаковыми. MMR добавляет разнообразие и уменьшает дублирование в контексте.
12. **Что такое reranker?** Reranker заново оценивает найденные кандидаты моделью, которая смотрит сразу на пару `вопрос - документ`. Это медленнее, но часто точнее простого сравнения embedding-векторов.
13. **Почему reranker сделан необязательным?** В задании он не обязателен, а локально он требует дополнительной модели и времени. Поэтому базовая система работает без него, а при необходимости он включается параметром `--rerank`.
14. **Почему ответ ограничивается контекстом?** Если не ограничивать модель, она может использовать общие знания и добавлять факты, которых нет в найденных документах. Для RAG важно, чтобы ответ опирался на переданные источники.
15. **Почему в prompt запрещено продолжать диалог и придумывать примеры?** Небольшие instruct-модели иногда продолжают формат обучающего диалога: добавляют новые вопросы, примеры и лишние блоки. Явное ограничение и постобработка ответа уменьшают такие повторы.
16. **Почему не используется API-модель?** Задание разрешает локальную модель или API. Локальная модель делает работу воспроизводимой без внешнего сервиса и не требует передачи данных во внешний API.
17. **Почему важны источники в ответе?** Источники позволяют проверить, из каких страниц был взят контекст. Это главное отличие RAG от обычной генерации текста: ответ должен быть связан с конкретными документами.
18. **Почему нельзя считать RAG полноценным дообучением модели?** При RAG веса LLM не меняются. Обновляется только внешняя база знаний и prompt, поэтому новые данные можно добавить без обучения модели.
